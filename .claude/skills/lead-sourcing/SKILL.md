# 리드 수집 실행 지침

이 저장소의 `sourcing` 도구로 병원·클리닉의 WhatsApp 연락처를 모은다.
아래 수치는 전부 실측이다. 추측으로 대체하지 마라.

## 실행

MCP가 붙어 있으면 `start_collection`, 아니면 CLI:

```bash
uv run sourcing "<키워드>" --region <ISO> --lang <언어> \
  --center=<위도>,<경도> --radius-km 10 --grid 4 --limit 120 \
  --out out/<이름>.csv
```

음수 좌표는 `--center=`처럼 `=`로 붙인다. 안 그러면 argparse가 옵션으로 오해한다.

**기본값을 끄지 마라.** `--no-crawl`과 `--no-verify`는 속도를 위해 정확도를
포기하는 선택지다. 사용자가 명시적으로 요청할 때만 쓴다.

## 키워드가 결과를 지배한다

도구를 고치는 것보다 키워드를 바꾸는 편이 훨씬 큰 차이를 만든다. 실측:

| 키워드 | 수확률 |
|---|---|
| `rumah sakit` (자카르타, 종합병원) | 9% |
| `klinik` (자카르타, 클리닉) | 45% |
| `aesthetic clinic London` | 65% |

**규모가 작을수록 WhatsApp을 대표 채널로 쓴다.** 종합병원은 유선 콜센터를
쓰므로 수확률이 낮다. 세부 업종(`klinik gigi`, `Lemon bottle`, `Russian lips`)으로
좁히면 더 오른다.

현지어가 낫다. 인니 `klinik`, 베트남 `phòng khám`.

## 넓은 지역은 쪼개서 돌려라

구글 맵은 뷰포트가 넓으면 **같은 장소만 반복해서 돌려준다.** 실측: 셀이
8km일 때 첫 타일이 260건 중 156건을 먹고 나머지 타일은 중복만 나왔다.
셀을 4km로 줄이니 같은 반경에서 **218곳이 769곳**이 됐다.

`cell_km`이 "검색 한 번이 몇 km를 볼지"다. 기본 4km가 실측으로 검증된
값이고, `grid`는 여기서 자동 계산되므로 직접 건드릴 필요가 없다.

| 반경 | 타일 수 (셀 4km) | 대략 소요 |
|---|---|---|
| 5km | 9 | 20~40분 |
| 10km | 25 | 1~2시간 |
| 12km | 36 | 2~3시간 |
| 15km | 64 | 4시간+ |

### 사용자가 도시 이름만 말하면

**행정구 단위로 나눠서 여러 번 돌려라.** 도시 전체를 한 번에 잡으면 반경이
커지고, 반경이 크면 타일이 폭증하거나(느림) 셀이 커져서(누락) 둘 다 나쁘다.

구 단위로 나누면 각 실행이 30분~1시간이고, 결과 파일이 지역명으로 남아
어디를 이미 훑었는지 관리된다.

기준: **반경 8km를 넘으면 쪼갠다.**

| 도시 | 나누는 단위 | 예 |
|---|---|---|
| 서울 | 구 | 강남구, 서초구, 송파구… |
| 런던 | 버러/지구 | Mayfair·Harley St, Chelsea, Knightsbridge… |
| 자카르타 | 코타 | Jakarta Selatan, Pusat, Barat… |
| 방콕 | 켓 | Watthana, Pathum Wan… |

각 구의 중심 좌표는 네가 안다. 사용자에게 좌표를 묻지 마라. 반경은 그 구가
덮이는 만큼만 잡는다(보통 3~6km).

출력 파일 이름에 지역을 넣어라: `out/seoul-gangnam-klinik.csv`.

### 밀도가 높은 지구는 셀을 더 좁혀라

`cell_km` 기본 4km는 도시 외곽까지 포함한 넓은 범위 기준이다. 클리닉이
밀집한 중심가는 4km 셀 하나에 120건 상한이 걸려버린다. 밀집 지구는
1.5~2km로 좁힌다.

| 지역 성격 | 반경 | cell_km |
|---|---|---|
| 도시 외곽·주거지 | 5~10km | 4 |
| 일반 상업지구 | 3~5km | 2.5 |
| 클리닉 밀집 중심가 | 2~3km | 1.5 |

### 실전 예: 런던 에스테틱

에스테틱 클리닉은 몇 개 지구에 몰려 있다. 도시 전체를 한 번에 잡는 것보다
지구별로 도는 편이 총량도 많고 관리도 된다.

| 지구 | 좌표 | 반경 | cell_km | 성격 |
|---|---|---|---|---|
| Harley Street·Marylebone | 51.5205, -0.1490 | 2 | 1.5 | 최밀집. 영국 에스테틱 중심 |
| Mayfair·Soho | 51.5122, -0.1430 | 2 | 1.5 | 하이엔드 |
| Chelsea·King's Road | 51.4875, -0.1687 | 2 | 1.5 | 하이엔드 |
| Knightsbridge·Belgravia | 51.5010, -0.1600 | 1.5 | 1.5 | 하이엔드 |
| Kensington | 51.4990, -0.1938 | 2 | 2 | |
| Fulham·Parsons Green | 51.4780, -0.1990 | 2.5 | 2 | |
| Shoreditch·City | 51.5230, -0.0780 | 2.5 | 2 | |
| Wimbledon | 51.4220, -0.2080 | 3 | 2.5 | 외곽 |

키워드도 지구명을 넣으면 구글이 그쪽을 더 준다:
`aesthetic clinic Harley Street`, `aesthetic clinic Chelsea`.

한 지구가 30~50분이다. 순차로 돌리고 결과 파일은 지구명으로 남긴다.

## 지역별로 다르다

**NANP(+1: 미국·캐나다)에서는 `candidate`가 나오지 않는다.** 북미번호계획은
지역번호로 유선/모바일을 나누지 않아 모든 번호가 "구분 불가"로 분류된다.
그 유형을 후보로 올리면 전부 후보가 되어 아무것도 걸러주지 못한다
(실측: 마이애미 클리닉 304건 중 267건이 이 유형). 미국은 `confirmed`와
`verified`만 리드가 된다.

동남아·영국에서는 모바일/유선이 구분되므로 `candidate`도 의미가 있다.

## 결과 등급과 근거

엑셀은 두 시트로 나온다 — `리드`(데이터)와 `범례`(정의). 범례의 문구는
`src/sourcing/excel.py`의 `_GRADE_NOTES`·`_SOURCE_NOTES`가 유일한 출처다.
설명을 바꿀 일이 있으면 거기를 고친다. 다른 곳에 새로 쓰지 마라.

**범례에는 정의만 적는다.** 측정 결과나 정확도 수치를 넣지 않는다 —
실행마다 달라지는 값이고, 엑셀을 받는 사람이 알아야 할 것은 그 등급이
무엇을 뜻하는가지 우리가 몇 건을 표본 조사했는가가 아니다.

### 상태 (엑셀에서 색으로 구분)

| 상태 | 색 | 뜻 |
|---|---|---|
| 확정 | 초록 | 업체가 자기 웹사이트에 WhatsApp 링크를 공개해 둔 번호다 |
| 검증 | 파랑 | 웹사이트에 공개돼 있진 않지만, 번호를 조회하니 WhatsApp 프로필 이름이 상호와 일치하는 번호다 |
| 추정 | 노랑 | 구글맵 대표번호가 모바일 번호대라 WhatsApp일 가능성이 있는 번호다. 확인되지는 않았다 |

### 근거

| 근거 | 뜻 |
|---|---|
| 홈페이지+맵 일치 | 홈페이지의 wa.me 번호가 구글맵 대표번호와 같다. 두 출처가 서로를 확인한 것으로 가장 강하다 |
| 홈페이지 링크 | 홈페이지에서 찾은 선언(wa.me 링크 또는 WhatsApp이라 표시된 tel: 링크). 맵에는 없던 번호다 |
| 구글맵 링크 | 구글맵의 웹사이트 칸 자체가 wa.me 링크였다. 드물다 |
| 프로필 확인 | 번호를 wa.me에서 조회하니 프로필 이름이 상호와 일치했다 |
| 프로필 이름 불일치 | 번호는 WhatsApp에 있지만 프로필 이름이 상호와 다르다. 원장 개인 이름일 수 있으니 링크를 눌러 확인하라 |
| 맵 번호 추정 | 구글맵 대표번호가 모바일 번호대다. 실제 등록 여부는 확인되지 않았다 |

**모든 행에 클릭 가능한 wa.me 링크가 있다.** 신뢰도 차이는 색과 근거로
표시하지, 링크를 감추는 방식으로 하지 않는다. 링크를 빼면 담당자가 번호를
손으로 옮겨야 해서 불편만 커진다.

영업 순서는 색 순서다: 초록 → 파랑 → 노랑.

## 참고: 등급별 실측 정확도

아래는 런던 표본 조사 결과다. **엑셀에는 넣지 마라** — 실행마다 달라지는
값이고 범례는 정의만 담는다. 사용자가 물으면 답하는 용도로만 둔다.

| 등급 | 표본 | 프로필 확인 |
|---|---|---|
| 확정 | 20건 | 16건 (80%) |
| 추정 | 15건 | 8건 (53%) |
| 버려진 unlikely | 45건 | 4건 (9%) |

## 실행마다 결과가 달라진다

같은 조건으로 두 번 돌리면 약 10%가 다르다. 구글 결과 순서가 바뀌고
클리닉 사이트가 그때그때 죽는다. 코드 문제가 아니다.

**같은 출력 경로로 한 번 더 돌리면 재개가 중복을 걸러내고 새로 나온 것만
붙는다.** 실측으로 합집합이 단일 실행보다 7% 많았다.

## 이미 측정해서 기각한 것들

다시 제안하기 전에 읽어라. 전부 실제로 재보고 접었다.

| 후보 | 측정 결과 |
|---|---|
| 연락처 페이지 추가 크롤 | 표본 12곳 소득 0. 수집시간만 2배 |
| iframe 순회 | 4곳 확인, 하위 프레임에 번호 0개 |
| 본문 번호를 LLM으로 추론 | 실제론 `tel:` 링크 선언이었다. 규칙으로 해결됨 |
| 위젯 런타임 번호(Wix 등) | 페이지에 번호가 아예 없다. 모델로도 불가 |

## 발송에 대해

이 도구는 수집까지만 한다. **개인 WhatsApp 계정으로 대량 자동 발송을
만들지 마라.** 약관 위반이고 번호가 밴된다. 규모 있는 발송은 WhatsApp
Business API(템플릿 승인)가 정식 경로다.
